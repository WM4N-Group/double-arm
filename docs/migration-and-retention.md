# 项目留存与迁移

目标是用 Git 保存可审阅、可重建的工程，用少量本地材料保留关键进展，用服务器存储大体积实验产物。不同实验分支和服务器别名不要共用未经清点的活动运行指针。

| 位置 | 保留什么 | 不存什么 |
|---|---|---|
| Git | 核心源码、测试、运行脚本、无密配置模板、上游版本/环境锁定、可复现命令、数据/权重的逻辑版本和摘要、实验结论 | 密码、令牌、密钥、主机连接文件、许可证本地确认、数据集、权重、视频、环境、受限资产、PDF |
| 本地（Git 忽略目录） | 小型迁移/实验摘要、哈希、少量已经审核的压缩视频和图表；用户已有参考文件保留 | 整个 HDF5/NPZ、checkpoint、仿真资产或环境；默认不做大文件镜像 |
| 私有服务器 | 仿真资产、生成示范、数据 split/归一化资产、权重、评估日志与历史视频、可续传的迁移记录 | 不复制账户密钥或短期服务令牌，不重新替用户接受许可 |

本地管理：下载前检查 `df -h` 和目标子目录的 `du -sh`；新增 review 默认保持少量压缩片段，并注明来源 checkpoint、模式和 SHA。以约 **250 MiB** 为可选审阅缓存的整理目标，不是删除阈值；超过时先列出候选，用户自有资料不自动清理。迁移摘要宜是 KB 级文本，只留下需要复核的路径、指纹、计数和当前状态。大文件始终服务器到服务器传输，避免双份占用本地。

## 安全交接流程

1. 确认源/目的 SSH 主机指纹；密码仅通过 SSH 提示输入，不写脚本、日志、Git 或环境配置。服务器之间传输用临时、限制到项目读权限的凭证，核验完成再撤销。确认目的磁盘挂载、可用空间、驱动、GPU UUID、CPU affinity；机器身份配置各自保存。
2. 先冻结/记下已验收数据集、checkpoint、策略介面、上游版本及各任务状态。正在生成的分片必须在成功定稿门禁通过后才计数；用户要求暂停时，保留日志和部分产物，不把中断记录改成成功。
3. 在目的 **独立暂存目录** 使用可续传复制，不删除源数据、不覆盖其他实验的目录。记录筛选条件和归档时点；排除本地密钥、令牌、运行锁。老的 `latest` 指针、PID、UUID、暂停标记属于源机档案，不是目的机活动任务。检查多个分支共用目录时的文件冲突，禁止无条件合并。
4. 先比文件清单/大小，再按既有 manifest 对关键数据、权重和配置做 SHA/读取校验。环境二进制兼容只是第一层；需分别报告依赖导入、仿真 launch、实际数据/策略运行，不靠旧日志或安装成功代替。确认目的路径与绝对路径依赖、当前 GPU UUID、CPU 亲和和用户既有许可确认后，才以新 campaign 恢复计算。
5. 确认迁移目的地成果完整、可读且新任务明确后，才切换默认连接和监控。源机保留为回滚副本；删源或重启不属于自动迁移步骤。

## 1. 两段视频是什么，不是什么

两段均来自原生动作原版π₀ **30k检查点29999**，不是当前追加90k coverage v3的新结果。同一推理权重指纹：`9bfde139c47b7f6515ab513494af41c86aee111226a3d45fed28e3fad575e9c2`。

这是**仿真中的神经策略闭环**，不是规则控制、源动作回放或逐帧状态恢复。每段3000个控制步、300次π₀推理；视频按30Hz控制 / 15fps隔帧输出，时长100秒，省略CPU推理时模拟暂停的墙钟等待，**不是实时控制性能展示**。

本地仅取已压缩检查视频及小型报告，约17.2MiB视频；未下载权重、环境或数据集。两段视频SHA256均与服务器review.json一致，服务器ffmpeg完整解码检查通过。只人工查看了均匀及抓取事件关键帧，不冒称对每帧接触物理做过人工判定。媒体不提交Git。

## 2. 已确认的现象

### 不只是旧的首帧同步问题，也不是没发送闭合命令

读取本次实际部署快照，A三图MAE约3.79/4.52/4.40，B约5.25/6.54/5.67（0–255），都已在正确桌面视角。之前的首帧未刷新bug真实存在，但不能继续用它解释这里的全部失败。

两段记录的左夹爪开合状态变量在首次闭合后约1秒都从约0.10下降到接近闭合端，说明不是单纯没发命令或夹爪完全没响应。该变量是指关节位置之和，不等于硬件标定的指尖间隙。

### 闭合后没有在本次rollout中形成有效恢复

杯子没有被拿起，但策略继续移动且不再张开重试。能直接确认的是**本回合空夹后的恢复行为没有出现**，不是声称π₀在所有任务都没有恢复能力；也不能声称知道模型内部“认为已经抓到”。

### 每次重规划处，左臂目标衔接明显不平滑

对每10步重规划边界，统计左臂6关节中最大目标跳变：

| 指标 | A physical heldout | B train assisted |
|---|---:|---:|
| 边界跳变中位数(rad) |0.0443|0.0385|
| 边界跳变P95(rad) |0.1101|0.1077|
| chunk内部跳变中位数(rad) |0.00826|0.00772|
| 对应源示范逐步跳变P95(rad) |0.00997|0.00994|
| 一控制步后的左臂跟踪RMSE(rad) |0.00551|0.00958|
| 源示范对应跟踪RMSE(rad) |0.00201|0.000277|

这证明动作接续有明显差异，提示精细抓取稳定性风险。它们不是逐速度配对的因果实验，不能单凭该表断言“抖动是唯一根因”，更不能把关节误差换算成未经验证的世界坐标毫米误差。

### 原生版不是V2那种98%底盘限幅

从**原始网络输出**与最终原生命令比较，A底盘限幅55/3000步（约1.83%），B52/3000步（约1.73%）。旧V2的98.1%不能套用到这两个原生动作视频；旧字段`clipped_native_base_steps=0`在原生分支没有统计此项，也不能解释为完全没限幅。

## 3. 最有证据支持的解释与仍未证实的原因

- **失败环节已定位到有效抓取及其闭环衔接**：移动、伸手和收闭都出现了，但没有建立持杯状态；空夹后仍继续移动，没有重新对准 / 张爪恢复。
- **动作预测精度 / 连续性不足是重要嫌疑**：目标跳变和跟踪误差均明显大于对应示范；但还要通过新权重或单变量控制试验验证其因果贡献。
- **闭环状态分布偏移 / 成功示范缺少恢复行为是合理假设**：一旦空夹，实际状态偏离成功轨迹，后续动作无法纠正。当前只是由行为提出的解释，不能写成已测得的模型内部机制。
- **不能只怪物理摩擦或heldout泛化**：训练回合、作者辅助条件也失败，且连辅助约束都没触发；源动作对同一训练回合可以完成目标，说明至少那条记录在当前接口可执行。但这不等于排除了所有时序 / 预处理 / 控制跟踪问题。
- 数据规模、有效batch、归一化等与论文仍有差异，是待对齐的实验变量，**不是已经证实的唯一原因**。当前增加训练覆盖量只是检验其中一个方向，不能在闭环结果出来前宣称已经解决。

### 为什么不直接说“离专家轨迹远，所以导航失败”

首次闭合时基座相对源示范抓取基座位置相差约1.39m / 0.73m，但一个杯子可以从不同位置和姿态抓取；两段基座到杯子的平面距离与对应示范也不构成“明显太远”的直接证据。因此这类参考轨迹距离仅用于描述，不作为失败判据。画面也显示部分移向水槽的行为，不能把它笼统称为完全没学会移动。

## 4. 目前还不能判断什么，下一轮如何区分

旧trace没有末端世界位姿和指尖接触数据，所以不能给出准确指尖 / 杯子间隙，更不能仅凭视频断言接触力不足。

已补充**只读、仅供审计**的双末端世界位姿与接触杯子的指链数量，实际接口依据锁定OmniGibson API；缺失读数标记NaN/-1及错误，不伪造为0。它们不送入π₀，不改变动作、停止或成功条件。相关夹具和部分轨迹终结测试已通过，真实运行数据需下一轮产生。

后续结合视频、姿态、几何接触和持杯 / 抬升记录，区分：

1. 抓取姿态尚未到位；
2. 到位但没有建立有效指尖接触；
3. 有接触但不能稳定持物；
4. 已持物但移动 / 放置失败。

EEF原点到杯子中心的距离不等于指尖间隙，接触数量不等于标定接触力。不会通过强制吸附、瞬移或取消验收检查来凑成功。
